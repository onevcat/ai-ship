In my local workflow, I’ve basically switched from Git to [jj](https://jj-vcs.github.io/jj/) and have used it continuously for a few months now. It feels great. The biggest change is not “fewer commands” or “faster operations,” but that its version-control mental model fits my current development rhythm much better.

Git is excellent and has been proven over two decades of collaboration. But it also reflects an earlier generation of software workflow. In the agent era, many everyday moves and history-management needs have shifted—and for me, jj feels more aligned with the way I think, easier for keeping history tidy, and better for frequent iteration and rewind.

This is not a diss on Git; it’s simply the choice that best fits my current workflow. If you’re also rethinking version control, check out my full write-up: [jj for Agent Era](https://onevcat.com/2026/03/jj-for-agent-era/), where I go deeper into both practical details and reasoning.
